## Error handling: what `describeError` maps and misses

`src/lib/db.ts:52-60` maps the **message text** only:
`duplicate key|already exists|already has an account` → duplicate · `row-level security|permission denied|insufficient|forbidden|42501` → forbidden · `Failed to fetch|NetworkError|fetch failed` → network · everything else → generic.

- Every `db.*` error (postgrest-js plain object) currently misses all three branches → generic (B-01, verified).
- `invokeFn` errors are real `Error`s whose message is the server's raw `fail()` text (`session.ts:212-220`). These do match, but a 500 leaks the raw DB message to `console` only and shows generic.
- Not mapped: 23502, 23503, 23514/P0001 custom messages (Texas guard, profile guard "Only an admin can change role…", tenant self-update guard), PGRST301/401, `organization_suspended`, app sentinels (B-11).
- `useToastMutation` (`queries.ts:150-183`) is used consistently. I found no raw `useMutation(` in routes or components. The only hand-written `toast.error(t("errors.generic"))` is clipboard copy (`portal.index.tsx:44`), which is acceptable.
